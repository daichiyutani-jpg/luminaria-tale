# 通信（QRコードで ともだちと遊ぶ）設計書

状態：**実装済み（サーバーなし・アカウントなし・費用なし）**。2026-11-04 の決定で、以前のサーバー方式の設計（部屋サーバー・署名つき受け取り証など）は取りやめ、下の方式に置きかえた。

## 1. 方針

- ひとり用は今後も完全オフライン。メニューの「つうしん」を開いただけでは どこにも通信しない
- 通信するのは、本人が「へやを つくる／ともだちの QRを よむ」を押した時だけ。相手の端末と**直接**つながる（WebRTC）
- 公開 STUN サーバー（`stun:stun.l.google.com:19302`）は、本人が「インターネットごしに つなぐ」に チェックした時だけ使う。チェックしなければ ICE サーバーなし＝同じ Wi‑Fi の中だけでつながる
- 対戦（直接対戦・QRチーム対戦）は**セーブを一切変えない**：経験値・お金・捕獲・道具なし、勝利数も数えない。チームは全回復したコピーで戦う
- 交換だけはセーブを変える（成立したら すぐ保存）
- 「つうしん」の画面と QR の部品（qrcode-generator / jsQR）は、画面を開いた時に読みこむ別ファイル（`link-*.js`）。Service Worker の事前キャッシュ（dist の全ファイル）に入るので、オフラインでも開ける（QRチーム対戦はオフラインで遊べる）

## 2. 遊び方

| モード | 流れ | 通信 |
| --- | --- | --- |
| ちょくせつ たいせん | A「たいせんの へやを つくる」→ QR を表示 → B「ともだちの QRを よむ」→ B に「へんじの QR」→ A が それを読む → つながる → チームを見せあって対戦 | WebRTC（相手と直接） |
| こうかん | 同じ手順で「こうかんの へや」。おたがいに1体えらぶ → 両方が「こうかんする」→ 成立 | WebRTC（相手と直接） |
| QRチーム たいせん | A「じぶんの チームQRを みせる」→ B「チームQRを よんで たたかう」→ A のチーム（CPU, smart 0.8）と対戦 | なし |

読み取りは3通り：カメラ（`getUserMedia`＋jsQR）／「しゃしんから よみとる」（`<input type=file accept=image/*>`）／「コードを はりつける」（QR の下の「コードを コピー」で送った文字）。
LINE などのアプリ内ブラウザでカメラが使えない時は、Safari（ブラウザ）で開き直すよう案内する。

## 3. QR の中身

### 3-1. つなぐための情報（`src/net/sdp.ts`）

ICE の候補が集まりきるのを待ち（trickle しない。3秒／STUN ありは6秒で打ち切り）、SDP から必要な所だけを取り出して短くする。読んだ側で データチャンネル用の SDP を組み立て直す。

```
LMO1~<モード b/t>~<STUN 0/1>~<ice-ufrag>~<ice-pwd>~<指紋(sha-256, base64url)>~<setup a/c/p>~<mid>~<候補>...~<チェック4けた>
LMA1~-~-~<ice-ufrag>~<ice-pwd>~<指紋>~<setup>~<mid>~<候補>...~<チェック4けた>
候補 = <種類 h/s/p/r><アドレス>:<ポート>    （UDP・コンポーネント1・重複なし・最大6個）
```

- 例：同じ Wi‑Fi（mDNS の host 候補1〜2個）で 120〜170 文字、STUN ありでも 600 文字未満
- 版が違う（`LMO2` など）時は「りょうほう さいしんに こうしんしてね」と案内して つながない

### 3-2. チーム（`src/net/team.ts`）

```
LMT1.<base64url(JSON)>.<FNV-1a チェックサム8けた>
JSON = { n: プレイヤー名, t: [[進化の記録[], レベル, 素質(16進6けた), 技ID[], ニックネーム?], ...] }
```

- HP・PP・状態異常は入れない（読む側で全回復）。1〜6体
- 読む時に1体ずつ `checkMonsterStrict`（`src/save/validate.ts`）で検査：存在しない灯獣・ボス・覚えられない技・レベル上限こえ・素質の範囲外・進化の記録の不整合 を拒否。チェックサムが合わない／欠けたコードも拒否
- 名前は制御文字・向きを変える文字を除き 12 文字まで

## 4. 直接対戦のしくみ（`src/net/match.ts`, `src/net/versus.ts`）

- つながったら両方が `hi`（通信の版・ゲームの版・モード・名前・合言葉）を送る。**ゲームの版が違うと対戦しない**（データや戦闘の計算が違うと結果がずれるため）
- 両方が自分のチームのコードを `team` で送る。**両方の端末が、同じ2つのコードから**チームを作る（ホスト側の灯獣の ID は `a0..`, ゲスト側は `b0..`）
- シード＝ホストの合言葉 ⊕ ゲストの合言葉×定数（片方だけでは決められない）。乱数は `seededRng`
- 戦闘の状態は「ホスト＝0、ゲスト＝1」の正本の並びで、両方の端末が同じ `src/logic/battle.ts` を動かす（ロックステップ）
  - 毎ターン、両方が自分の行動だけを `act { n, a, h }` で送る。`h` はターン前の状態の要約。番号か要約が合わない・相手の行動が不正（道具・捕獲・にげる・PP切れの技・たおれた灯獣への交代）なら「ずれ」として**勝負を中止（どちらの勝ちにもしない）**
  - たおれた後の交代は、たおれた側だけが `sw { n, to }` を送る。両方が交代する時も、必ず 0→1 の順に入れる
  - ゲストの画面は、正本を反対向きに見せる `mirrorState()` と、出来事の向きを入れかえて表示する。文章は `state.pov`（下記）で ゲスト側から書かれる
- こうさん：`gg` を送る（送った側は負け、受けた側は勝ち）
- 切断：データチャンネルが閉じる／ICE が failed／30秒なにも届かない（4秒ごとに ping）→「つうしんが きれてしまった」＋「この勝負は なかったことに」
- 単体テスト（`tests/net.test.ts`）で、ホストとゲストの2つのエンジンに同じ行動を入れると 最後まで同じ状態になることを6つのシードで確認している

### 戦闘処理（src/logic/battle.ts）への小さな追加

`BattleState.pov?: SideIndex`（省略時 0）を足した。「あいての ○○」「もどれ、○○！」「あなたは ○○を つかった！」の**文章をどちら側から書くか**だけに使い、計算の結果は変わらない。ひとり用の動きは今までと同じ。

## 5. 交換のしくみ（`src/net/trade.ts`）

1. おたがいに1体えらぶ → `offer { id, mon }`（必要な項目だけ）。受けた側は `checkMonsterStrict` などで検査し、だめなら `nope` で理由を返す
2. 両方が「この ないようで こうかんする」→ `ok { mine: 自分の offer id, theirs: 相手の offer id }`。**どちらかが えらびなおすと、両方の OK は取り消し**
3. 自分の OK を送り、相手の OK（id が今の組み合わせと一致）を受けたら成立：送った灯獣をセーブから外し、受け取った灯獣に **新しい UID**（`issueUid`）と **元の持ち主**（`originalTrainer`、すでにあれば そのまま）を付けて全回復で加える → 図鑑・クエストを更新 → **すぐ保存**
- パーティーの最後の1体は だせない。パーティーとボックスの どちらからでも だせる
- 制限：サーバーがないので、成立の瞬間に通信が切れると 片方だけ成立する（複製・消失が起こりうる）。ともだち同士で遊ぶ前提の割り切り。改造した端末からの「改造データ」は検査で防ぐが、同じ灯獣を2台にコピーして交換する、といった不正は防げない

## 6. 確認できていること／できていないこと

- 確認済み：単体テスト（チームのコードの往復・チェックサム・改造の拒否、SDP の圧縮→組み立て直しの往復、QR 生成→読み取りの往復、2エンジンのロックステップ、交換の成立と拒否）、ブラウザの総合テスト（`scripts/e2e.mjs`：オフラインで「つうしん」を開く、QRチーム対戦、同じブラウザの2タブを コードの はりつけで つないでの 直接対戦と交換、外部ドメインへの通信がないこと）
- 未確認：**実機2台での確認**（スマホ同士の同じ Wi‑Fi、カメラでの読み取り、iPhone Safari と Android Chrome の組み合わせ、STUN を使ったインターネットごしの接続）。携帯回線どうし（対称 NAT）では、TURN サーバーがないため つながらないことがある
